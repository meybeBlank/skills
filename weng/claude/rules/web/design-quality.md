# Web设计质量标准

## 反模板政策

不要交付看起来通用模板的UI。前端输出应该看起来是有意图的、有主见的、并且是特定于产品的。

### 禁止的模式

- 具有均匀间距和无层次感的默认卡片网格
- 带有居中标题、渐变blob和通用CTA的库存英雄区域
- 未经修改的库默认值被当作最终设计
- 无分层、无深度、无动画的扁平布局
- 每个组件都使用均匀的圆角、间距和阴影
- 只有一个装饰性强调色的安全灰白样式
- 具有侧边栏+卡片+图表但无观点的数据仪表板布局
- 在没有明确理由的情况下使用默认字体堆栈

### 必需的质量

每个有意义的前端界面应至少展示以下四项：

1. 通过比例对比形成的清晰层次
2. 有意的间距节奏，而非到处都是均匀的内边距
3. 通过重叠、阴影、层或动画形成的深度或分层
4. 有特色的排版和真正的配对策略
5. 语义化的颜色使用，而不仅仅是装饰性的
6. 看起来经过设计的悬停、焦点和激活状态
7. 在适当的地方使用打破网格的编辑或便当布局
8. 符合视觉方向的纹理、颗粒或氛围
9. 明确流程而非分散注意力的动画
10. 数据可视化作为设计系统的一部分，而非事后才想到的

## 编写前端代码之前

1. 选择一个具体的风格方向。避免"简洁极简"之类的模糊默认值
2. 有意地定义调色板
3. 深思熟虑地选择排版
4. 收集至少一小套真实的参考
5. 在相关地方使用ECC design/frontend技能

## 值得考虑的风格方向

- 编辑式/杂志式
- 新粗野主义
- 具有真正深度的玻璃拟态
- 暗色奢华或亮色奢华与严谨的对比
- 便当布局
- 滚动叙事
- 3D集成
- 瑞士/国际风格
- 复古未来主义

不要自动默认使用深色模式。选择产品实际想要的视觉方向。

## 组件检查清单

- [ ] 它是否避免了看起来像默认Tailwind或shadcn模板？
- [ ] 它是否有经过设计的悬停/焦点/激活状态？
- [ ] 它是否使用层次而非均匀强调？
- [ ] 这在一个真实的产品截图中看起来可信吗？
- [ ] 如果支持两种主题，亮色和暗色是否都经过有意设计？
