# 流程节点：Git 提交

流程节点：BDD 代码提交
描述: 作为工作流终点，汇总全流程产出，生成符合 Conventional Commits 规范的提交信息，经用户确认后完成提交和/或推送操作，最后向用户汇报工作摘要。

## 系统指令

你现处于**代码提交阶段**，是整个 BDD 工作流的终点。你的职责是汇总全流程产出、生成提交信息、在用户确认下完成 git 提交与推送，并汇报工作摘要。

**强制用户确认（引擎规则）**：

用户必须手动确认后才能执行 git 操作。确认选项为：
- **提交并推送**：执行 `git commit` + `git push`
- **仅提交**：执行 `git commit`，不推送
- **不处理**：跳过提交和推送

未获确认不得执行对应操作。

## 前置条件

- 全量测试全部通过且覆盖率达标（或经用户确认放行）
- 所有代码改动已完成

## 执行流程

### 1. 汇总工作流产出

回顾整个工作流各节点存档（trace_path 下的结果包），提取：新增/修改文件清单、测试数量（三层）、审查通过轮次、回退历史。

### 2. 生成提交信息草稿

基于汇总信息生成符合 Conventional Commits 规范（对齐 git-workflow 规则：feat/fix/refactor/docs/test/chore/perf/ci）的提交信息：

```
<type>(<scope>): <简短描述>

## 变更摘要
- <改动要点1>
- <改动要点2>

## 测试覆盖
- 单元测试：{count} 个，全部通过
- 集成测试：{count} 个，全部通过
- 功能测试：{count} 个 Scenario，全部通过
- 覆盖率：{X}%

## 审查记录
- 契约审查：通过（{迭代次数} 轮）
- 测试审查：通过（{迭代次数} 轮）
- 代码审查：通过（{迭代次数} 轮）

## 回退历史
- {如有回退，列出每次回退原因；无则"无"}

@fengz
```

### 3. 提交前安全自检

提交前对照安全规则逐项核对（引擎级质量兜底）：

- [ ] 无硬编码 secrets（API 密钥、密码、token）
- [ ] 改动范围与本次功能一致，无误提交的无关文件/调试代码
- [ ] 无 `console.log` 等调试语句遗留
- [ ] **前后端完整性核对**（全栈项目必检）：
  - 验证矩阵中标记"纯后端"的场景 → 对应后端测试/实现已落盘
  - 验证矩阵中标记"纯前端"的场景 → 对应前端测试/实现已落盘
  - 验证矩阵中标记"前后端组合"的场景 → 后端代码+前端代码均已实现，测试通过
  - 验证矩阵"前端测试"列的非空场景 → 前端测试文件已落盘（`src/**/__tests__/*.test.js` 或 `tests/e2e/*.spec.js`）
  - 验证矩阵后端三层非空的场景 → 后端测试文件已落盘（`tests/unit/` / `tests/integration/` / `tests/e2e/`）
  - 无"验证矩阵有计划但无对应代码/测试"的场景

发现问题立即停止，让用户决策

### 4. 用户确认并执行

1. 展示提交信息草稿与 `git status` / `git diff --stat` 改动概览。
2. **请求用户确认操作方式**，提供三个选项：
   - **提交并推送**：执行 `git commit` + `git push`
   - **仅提交**：执行 `git commit`，不推送
   - **不处理**：跳过提交和推送

> 说明：本节点以标准 git 命令完成提交与推送。若项目后续引入 `git_commit_push` 等提交 skill，可在此替换为对该 skill 的调用（当前仓库未提供该 skill，不作依赖）。

### 5. 工作摘要汇报

任务完成后，向用户汇报：

- 本次功能实现的核心价值与覆盖场景数
- 三层测试数量与最终覆盖率
- 三个审查阶段的通过轮次与回退历史
- 提交/推送状态（commit hash、是否已推送远程）
- 遗留的待确认事项（如各结果包中未闭环的 TODO）

## 节点跳转

任务完成，工作流结束。
