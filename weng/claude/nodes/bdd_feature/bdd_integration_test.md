流程节点：BDD 前后端联调测试
描述: 后端和前端管线均完成后，启动后端服务、运行前端 Playwright E2E 全量测试，验证前后端完整链路贯通，并核对前端 API 调用与后端契约的一致性。

# 前后端联调测试阶段

## 系统指令

你现处于**前后端联调测试阶段**，以自动流程节点身份验证后端已实现的 API 与前端已实现的页面能正确串联。

输入：
1. **验证矩阵结果包**（"前后端组合"场景清单）
2. **架构基线结果包**（后端启动命令、前端 dev server 启动命令、E2E 运行命令）
3. **API 契约文件**（`<doc>_契约.<ext>`）
4. **后端开发结果包**（确认后端 API 已实现并通过测试）
5. **前端开发结果包**（确认前端页面已实现并通过 Vitest）

任务：启动后端服务 → 运行前端 Playwright E2E 全量 → 核对契约一致性 → 产出联调结果。

## 核心原则

1. **真实链路**：联调使用真实的后端服务（测试数据库），不 mock 后端
2. **端到端验证**：从浏览器用户操作到数据库变更，完整验证
3. **契约一致性**：逐一核对前端 API 调用的字段名/类型/枚举值与契约
4. **如实报告**：失败即失败，不做推断粉饰

## 前置条件

- 后端开发子流程已 PASS（后端 API 已实现，后端测试全部通过）
- 前端开发子流程已 PASS（前端页面已实现，Vitest 单元测试全部通过）

若任一条件不满足，本节点不应被进入。

## 步骤 1：启动后端服务

1. 从架构基线提取后端启动命令
2. 使用测试数据库（`FAMILY_DB_PATH` 环境变量或项目既有约定）
3. 启动后端服务，等待就绪（健康检查 `GET /docs` 或 `GET /api/v1/records/categories` 返回 200）
4. 若启动失败，记录为环境问题，修复后重试

## 步骤 2：运行前端 Playwright E2E 全量

1. 启动前端 dev server（代理到刚启动的后端服务）
2. 运行 `cd frontend && npm run test:e2e`
3. 记录所有通过/失败用例

## 步骤 3：契约一致性核对

对照契约文件，逐一核对前端 API 调用的以下维度：

| 核对维度 | 检查方式 | 示例 |
|:---|:---|:---|
| 请求字段名 | 检查 `endpoints.js` 中 fetch 的 body 字段名 | 契约 `recorder` → 前端用 `recorder`，不是 `recorderName` |
| 响应字段解析 | 检查前端解析 response 的字段名 | 契约返回 `reasonability` → 前端解构 `data.reasonability` |
| 枚举值映射 | 检查前端枚举值与契约一致 | 契约 `"必要"/"可降低"/"可取消"` → 前端 picker 选项一致 |
| 分页参数 | 检查前端分页请求参数名 | 契约 `page`/`page_size` → 前端用 `page`/`page_size` |

核对结果写入联调结果：

```
契约一致性核对：
| 核对项 | 契约定义 | 前端实现 | 结果 |
|--------|---------|---------|:---:|
| 创建记录 - recorder 字段 | `recorder: string` | `recorder` ✅ | ✅ 一致 |
| 列表分组 - period 参数 | `period: "day"/"week"/"month"` | `period` ✅ | ✅ 一致 |
```

## 步骤 4：结果判定

| 结果 | 处理 |
|:---|:---|
| Playwright E2E 全绿 + 契约一致 | → 跳转`全量测试` |
| Playwright E2E 存在失败 → 判定为前端缺陷 | → 回退`前端开发`子流程（计入联调回退环熔断） |
| Playwright E2E 存在失败 → 判定为后端 API 不符契约 | → 回退`后端开发`子流程（计入联调回退环熔断） |
| Playwright E2E 存在失败 → 无法判定责任端 | → 上报用户决策 |
| 契约不一致 | → 上报用户确认后回退对应管线 |

**回退熔断**：联调回退环连续回退达 3 次 → 停止自动回退，上报用户卡点。

失败分类指南：
- 前端缺陷特征：Playwright 报错元素找不到、断言 UI 文案不匹配、前端请求未发出
- 后端缺陷特征：Playwright 报错 API 返回 500、返回结构与契约不一致、数据库状态异常
- 契约不一致：字段名/类型/枚举值与契约文件不同

## 质量门禁

| 检查项 | 通过标准 |
|:---|:---|
| 后端就绪 | 后端服务已启动并可通过健康检查 |
| E2E 全量通过 | Playwright 全部场景通过，无失败/跳过 |
| 契约一致 | 前端 API 调用的字段名/类型/枚举值与契约一致 |
| 无环境问题 | 失败均来自代码缺陷，非环境/配置问题 |

**最终判断信号**：
1. 前后端完整链路是否贯通（E2E 全绿）？
2. 前端 API 调用是否与后端契约一致？
3. 不一致或失败是否已明确路由到正确的责任端？
