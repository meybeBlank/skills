# Android 项目范式 Profile

定义 **Android 类项目**在 BDD 流程中受项目结构影响的四处形态。流程骨架（红灯机制、分批、转绿顺序、覆盖率口径、回归范围等）由节点文件承载，与项目类型无关；本文件只定形态。

由`架构勘察`选定并写入架构基线，下游节点按需读取对应章节。本文件给"选项集合与默认"，具体框架版本/目录/命令/标注符号由架构勘察从真实代码探测；形态冲突以本文件为准。

## 适用判定

命中任一即选本 profile：AGP + `AndroidManifest.xml`；依赖含 `androidx.*`/`android.*`；测试栈含 Robolectric/AndroidJUnitRunner/Espresso。多形态并存是常态，各层按真实探测分别选定。

## 一、契约产出形态

Android 跨边界接口以**进程内接口**为主，无 HTTP/OpenAPI。

| 交互形态 | 契约形式 | 落盘 |
|:---|:---|:---|
| 模块间 Kotlin/Java interface | 接口签名表 | `<doc>_契约.md` |
| AIDL/Binder 跨进程 | 签名表 + `.aidl` 引用 | `<doc>_契约.md` |
| 广播/Intent/事件总线 | 事件契约表（action、extras 字段与类型、触发/消费方、关联场景） | `<doc>_契约.md` |

**签名表内容**：接口名、方法签名、每个参数与返回值语义、返回值枚举全量取值、契约常量、契约级不变量（调用顺序/线程模型/生命周期）、关联场景。失败语义以返回值枚举或异常类型表达（替代 HTTP 的统一 ApiError）。集成测试断言签名/枚举/不变量，而非状态码。

**自检**：每方法可追溯至少一个集成测试场景；枚举取值语义完整；增量更新时既有签名未误删，签名/语义 Breaking 变更（改参数/返回类型/枚举语义/删方法）列入待确认。

**契约跳过**：集成层非空但仅消费既有接口（未改任何方法签名/返回值语义）时跳过契约与契约审查，集成测试直接针对既有签名编写。

## 二、测试分层形态

功能层**不以 Cucumber 为默认**，以项目既有端到端手段承载；Gherkin 作需求锚点保留。

| 层 | 选项 | 默认 | 隔离 |
|:---|:---|:---|:---|
| 功能层（E2E） | Robolectric 真实组件串联 / Espresso 设备端 / 既有 Cucumber-Android | Robolectric 真实串联 | 仅隔离硬件/系统/跨进程边界（mockStatic/Shadow/seam），**业务组件用真实实现** |
| 集成层 | 模块真实串联组件测试（Robolectric 或纯 JVM） | Robolectric 组件测试 | Mock/Fake/Shadow 隔离外部依赖，业务模块真实 |
| 单元层 | 纯 JVM（JUnit + Mock + 断言库） | 纯 JVM | Mock 隔离一切外部依赖 |

**功能层承载**：有可运行端到端手段（Robolectric 串联/Espresso/Cucumber-Android）→ 产出可执行端到端测试，Gherkin 逐条对应一个用例——**Robolectric 真实串联是首选合法承载，非降级**。确无任何端到端手段 → Gherkin 降级为需求载体，端到端验证下沉集成层，功能层标注"无 E2E 手段，下沉集成层"。

E2E 价值在真实组件串联，只有硬件/系统/跨进程边界打桩——分层时不得因未做全 Mock 而错分到单元层，也不得因无 Cucumber 而强制下沉。

## 三、审查探测方式

**场景 ID 标注**（Android 常用 JUnit4，无 `@Tag`）：以架构勘察探测的既有惯例为准，常见反引号描述性方法名、方法名内嵌 ID、KDoc/注释场景 ID（如 `AC-EC03`）。

```bash
grep -rn '@Test' <测试目录> -A1 | grep -oE '`[^`]+`|AC-[A-Z]+[0-9]+|[A-Z]+-[A-Z]+-[0-9]+' | sort -u
```

**契约核对**：核对 `<doc>_契约.md` 签名表——每方法可追溯集成测试、返回值枚举语义完整、契约常量与不变量齐全（替代 OpenAPI `$ref`/ApiError 核对）。

**绿灯真实性**：以架构勘察提取的实际命令验证（如 `./gradlew :<module>:testDebugUnitTest`）。

## 四、覆盖率工具落地

工具以架构勘察探测为准，常见 Jacoco（`jacocoTestReport`）。

**改动覆盖率提取**：Jacoco 默认产出全量报告，从中按 git diff 的改动文件清单与 `+` 行过滤——定位改动文件的行/分支数据，或用 per-line 数据（`<line nr ci mi>`）与 diff `+` 行号取交集。门禁：改动文件/模块行覆盖率 ≥ 80%、改动代码无未测分支；全量行覆盖率仅作回归参考。无工具时标注"覆盖率无法量化"交用户决策。

## 兜底

探测到的子形态不在本 profile 选项集内时，标注"无先例"，给建议形态经用户确认后采用并记入架构基线。
