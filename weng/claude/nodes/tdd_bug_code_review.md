流程节点：TDD 代码审查
描述: 编排节点。调用 `bdd-stage-reviewer`（阶段参数 `code-green`）在隔离上下文审查 git 改动，主 agent 只编排与存档，不直接审查。审查清单由子 agent 自身承载，本节点只说明 bug 流程与 BDD 的语境差异。

# 代码审查阶段

## 系统指令

本节点是**编排节点**，不是执行节点。实际审查由 `bdd-stage-reviewer` 子 agent（阶段参数 `code-green`）在隔离上下文完成，审查清单与输出格式见 `.claude/agents/bdd-stage-reviewer.md`，本节点不重复。

主 agent 只做三件事：传输入、传语境注疏、存档。

## 输入

1. **问题理解结果包**（回归范围圈定）
2. **架构基线结果包**（编码约定、测试运行命令、范式 profile）
3. **代码修改结果包**、**代码重构结果包**（实现与重构改动）
4. **测试用例开发结果包**（复现固化+扩展测试、回归保绿基线、追溯表）
5. 当前 git diff

## 语境注疏（传给子 agent）

`bdd-stage-reviewer` 的 code-green 阶段为 BDD 流程设计，含契约/验证矩阵语境项。bug 流程无这两类上游，调用时须向子 agent 明示以下差异，其余清单项全部按原样核对：

- **契约一致** → 跳过。bug 流程无契约阶段，无契约文件可核对，**不得因"未核实契约"判定阻断**。
- **回归合规** → 回归基准换源：以"问题理解结果包·回归范围圈定"+"测试用例开发结果包·回归保绿基线"替代 BDD 的"验证矩阵回归范围"。
- **覆盖核对** → 覆盖基准换源：以"测试用例开发结果包·追溯表"（复现固化+扩展用例 vs bug 触发条件/关联模块缺口）替代 BDD 的"验证矩阵场景"。
- **全局换源总则**：子 agent code-green 清单中凡提及"验证矩阵""场景ID""补充用例 SUP-xx""批D补充覆盖"等 BDD 验证矩阵语境处，一律换源为——场景ID→测试用例开发追溯表用例标识；验证矩阵回归范围→问题理解回归范围+测试红保绿基线；补充用例→测试红系统化扩展用例。**不得因"未对应验证矩阵某场景ID"判定阻断**；抽查可追溯性时以测试红追溯表为准。
- **副作用剥离自检/签名同步简化**：这两项原为 BDD 解耦重构设计，bug 修复型若本次改动未涉及删除/简化既有逻辑段，直接标注"本改动无副作用剥离/签名同步场景，不适用"放行；若涉及则按原样核对。

## 执行

1. 确认前置：代码重构全绿且回归未变；git diff 审查范围已界定。
2. 调用 `bdd-stage-reviewer`（阶段 `code-green`），传入上述输入与语境注疏，在隔离上下文审查。
3. 子 agent 返回后，将审查报告原文写入 `trace_path/<doc>_代码审查报告.md`（单文件存档，`doc` = `<序号>_代码审查`）。报告格式沿用子 agent 的"审查输出格式"。

**编排约束**：主 agent 不直接审查实现代码；子 agent 拥有 Read/Grep/Glob/Bash，自行读码与运行测试。

## 节点跳转

- PASS → `全量测试`
- FAIL → `代码修改`（连续 FAIL 达 3 次触发回退熔断，上报用户）
