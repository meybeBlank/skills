# BDD 前端开发子流程

**子流程上下文**：
- 调用方：主流程 `weng_bdd_feature.md` 的"前端开发"复合节点
- trace_path：`<主trace_path>/frontend/`
- 输入白名单：主流程传递的验证矩阵、架构基线、契约、Gherkin 文件，以及后端子流程结果包
- 输出：`前端开发结果包.md`
- 回退熔断：子流程内部独立计数，同一回退环达 3 次 → 返回 FAIL 给主流程

**核心规则**：
1. 严格遵守主流程引擎的节点跳转、归档、审查隔离、回退熔断规则
2. **节点结果存档**：在项目的`trace_path`目录下对各个流程节点的最终产出内容进行存档，节点重复进入时，不更改已存在的产出内容，新建存档文件追加产出内容
3. **执行范围限定**：只处理验证矩阵中**"前端测试"列非空**的场景行
4. **后端 API 依赖**：前端代码开发依赖后端 API 已就绪（通过读取 `后端开发结果包.md` 确认）
5. **契约不一致**：前端 API 调用参数/响应解析与后端契约的一致性核对，不一致则返回 FAIL 给主流程，将遇到的问题记录到结果包

**子流程结果**：PASS 时汇总产出 `前端开发结果包.md`，格式如下：

```markdown
# 前端开发结果包

## 1. 执行摘要
- 状态：PASS / FAIL
- 场景覆盖：{N}/{M} 个前端场景已完成
- 测试类型：Vitest 单元测试 + Playwright E2E

## 2. 各阶段记录
| 阶段 | 节点 | 状态 | 关键指标 |
|:---|:---|:---|:---|
| 红 | 前端测试用例 | PASS | {N} 个红灯测试 |
| 审查 | 前端测试审查 | PASS | 第 {K} 轮通过 |
| 绿 | 前端代码开发 | PASS | {M} 个测试转绿 |
| 重构 | 前端代码重构 | PASS | {X} 处重构 |
| 审查 | 前端代码审查 | PASS | 无阻断项 |

## 3. 实现文件清单
（新增/修改的前端文件路径列表）

## 4. 契约一致性核对
（前端 API 调用参数/响应解析与后端契约的一致性核对结果）

## 5. 未解决问题
（无则"无"）

## 6. 回退历史
（子流程内部的回退记录，无则"无"）
```

## 节点：前端测试用例（红）

**流程编排规则文件**：`.claude/nodes/bdd_feature/bdd_test_red_frontend.md`

**执行范围**：只处理验证矩阵中**"前端测试"列非空**的行

**节点输入**：
  - 首次进入：`<doc>_验证矩阵结果包.md`、`<doc>_架构基线结果包.md`、`<doc>_契约.<ext>`（如果存在）、`<主trace_path>/backend/后端开发结果包.md`
  - 从`前端测试审查`节点进入：`<doc>_前端测试审查报告.md`

**节点结果**：`<doc>_前端测试用例开发结果包.md`（前端场景清单、Vitest/Playwright 红灯测试、批次状态）

**下一个节点**：`前端测试审查`

## 节点：前端测试审查

**流程编排规则文件**：`.claude/agents/bdd-stage-reviewer.md`

**子agent**：`bdd-stage-reviewer`（阶段参数 `test-red-frontend`），必须使用子agent在独立上下文中审查，禁止在主agent中直接审查

**节点输入**：`<doc>_验证矩阵结果包.md`、`<doc>_前端测试用例开发结果包.md`

**节点结果**：
 - 审查结论：PASS/FAIL、`<doc>_前端测试审查_审查报告.md`
 - 文件落盘：子agent 返回结构化审查报告后，**必须将审查报告原文写入** `trace_path/<节点执行序号>_前端测试审查_审查报告.md`

**下一个节点**：
  - PASS → `前端代码开发`
  - FAIL → `前端测试用例`修改测试（连续 FAIL 达 3 次触发回退熔断，**返回 FAIL 给主流程**）

---

## 节点：前端代码开发（绿）

**流程编排规则文件**：`.claude/nodes/bdd_feature/bdd_code_green_frontend.md`

**执行范围**：只编写前端实现代码（Vue 页面/组件/API 调用层），使前端红灯测试转绿。不涉及后端代码。

**节点输入**：
  - 首次进入：`<doc>_前端测试用例开发结果包.md`、`<doc>_验证矩阵结果包.md`、`<doc>_架构基线结果包.md`、`<doc>_契约.<ext>`（如果存在）、`<主trace_path>/backend/后端开发结果包.md`
  - 从`前端代码审查`节点进入：`<doc>_前端代码审查报告.md`

**节点结果**：`<doc>_前端代码开发结果包.md`（批次转绿状态、实现文件清单、绿灯确认、自检记录、待确认事项）

**下一个节点**：`前端代码重构`

---

## 节点：前端代码重构

**流程编排规则文件**：`.claude/nodes/bdd_feature/bdd_refactor.md`

**子agent**：`code-refactorer`（`.claude/agents/code-refactorer.md`），必须使用子agent在独立上下文中对当前**前端 git diff**的实现代码执行结构优化，禁止在主agent中直接重构

**节点输入**：
  - `<doc>_前端代码开发结果包.md`（实现文件清单、绿灯确认、自检遗留项）
  - `<doc>_架构基线结果包.md`
  - `<doc>_契约.<ext>`（如果存在，重构须保持前端 API 调用与契约一致）
  - `<doc>_验证矩阵结果包.md`（回归范围，重构后须保绿）
  - 当前前端 git diff（本次绿阶段前端实现改动，重构对象）

**节点结果**：`<doc>_前端代码重构结果包.md`（重构清单、绿验证复核记录、未重构项、契约保持核对、待确认事项）

**下一个节点**：
  - 全绿且 API 调用与契约一致 → 跳转`前端代码审查`
  - 存在回红且无法自修 → 跳转`前端代码开发`修复（计入代码重构回退环熔断计数，连续回退达 3 次触发熔断，**返回 FAIL 给主流程**）
  - API 调用与契约不一致 → 上报用户决策是否回退到主流程的`API契约`节点（属契约变更范畴，不计入回退熔断）

---

## 节点：前端代码审查

**流程编排规则文件**：`.claude/agents/bdd-stage-reviewer.md`

**子agent**：`bdd-stage-reviewer`（阶段参数 `code-green-frontend`），必须使用子agent在独立上下文中审查前端 git 改动，禁止在主agent中直接审查

**节点输入**：`<doc>_验证矩阵结果包.md`、`<doc>_架构基线结果包.md`、`<doc>_契约.<ext>`（如果存在）、`<doc>_前端代码开发结果包.md`、`<doc>_前端代码重构结果包.md`

**节点结果**：
 - 审查结论：PASS/FAIL、`<doc>_前端代码审查_审查报告.md`
 - 文件落盘：子agent 返回结构化审查报告后，**必须将审查报告原文写入** `trace_path/<节点执行序号>_前端代码审查_审查报告.md`

**下一个节点**：
  - PASS → 汇总各阶段记录，生成 `前端开发结果包.md`，**返回 PASS 给主流程**
  - FAIL → `前端代码开发`修改代码（连续 FAIL 达 3 次触发回退熔断，**返回 FAIL 给主流程**）

---

## 子流程结束

代码审查 PASS 后：
1. 汇总各节点记录到 `前端开发结果包.md`
2. 返回 PASS 给主流程；主流程读取本结果包判断是否进入下一阶段
