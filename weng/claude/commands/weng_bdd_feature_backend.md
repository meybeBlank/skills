# BDD 后端开发子流程

**子流程上下文**：
- 调用方：主流程 `weng_bdd_feature.md` 的"后端开发"复合节点
- trace_path：`<主trace_path>/backend/`
- 输入白名单：主流程传递的验证矩阵、架构基线、契约、Gherkin 文件
- 输出：`后端开发结果包.md`
- 回退熔断：子流程内部独立计数，同一回退环达 3 次 → 返回 FAIL 给主流程

**核心规则**：
1. 严格遵守主流程引擎的节点跳转、归档、审查隔离、回退熔断规则
2. 需求变更回退不属本子流程范围——需求问题回退到主流程的`需求理解`节点，由主流程处理
3. **执行范围限定**：只处理验证矩阵中**后端三层（功能测试/集成测试/单元测试）非空**的场景行，忽略"纯前端"行和"前端测试"列

**子流程结果**：PASS 时汇总产出 `后端开发结果包.md`，格式如下：

```markdown
# 后端开发结果包

## 1. 执行摘要
- 状态：PASS / FAIL
- 场景覆盖：{N}/{M} 个后端场景已完成
- 红灯批次：批A: ✅ / 批B: ✅ / 批D: ✅ / 批C: ✅

## 2. 各阶段记录
| 阶段 | 节点 | 状态 | 关键指标 |
|:---|:---|:---|:---|
| 红 | 后端测试用例 | PASS | {N} 个红灯测试 |
| 审查 | 后端测试审查 | PASS | 第 {K} 轮通过 |
| 绿 | 后端代码开发 | PASS | {M} 个测试转绿 |
| 重构 | 后端代码重构 | PASS | {X} 处重构 |
| 审查 | 后端代码审查 | PASS | 无阻断项 |

## 3. 实现文件清单
（新增/修改的后端文件路径列表）

## 4. 未解决问题
（无则"无"）

## 5. 回退历史
（子流程内部的回退记录，无则"无"）
```

## 节点：后端测试用例（红）

**流程编排规则文件**：`.claude/nodes/bdd_feature/bdd_test_red.md`

**执行范围**：只处理验证矩阵中**后端三层**（功能测试/集成测试/单元测试列）非空的行，忽略"纯前端"行

**节点输入**：
  - 首次进入：`<doc>_Gherkin场景文件.md`、`<doc>_验证矩阵结果包.md`、`<doc>_架构基线结果包.md`、`<doc>_契约.<ext>`（如果存在）
  - 从`后端测试审查`节点进入：`<doc>_后端测试审查报告.md`

**节点结果**：`<doc>_后端测试用例开发结果包.md`（批次划分、三层红灯测试、验证矩阵追溯、批次状态、待确认事项）

**下一个节点**：`后端测试审查`

## 节点：后端测试审查

**流程编排规则文件**：`.claude/agents/bdd-stage-reviewer.md`

**子agent**：`bdd-stage-reviewer`（阶段参数 `test-red`），必须使用子agent在独立上下文中审查，禁止在主agent中直接审查

**节点输入**：`<doc>_验证矩阵结果包.md`、`<doc>_后端测试用例开发结果包.md`

**节点结果**：
 - 审查结论：PASS/FAIL、`<doc>_后端测试审查_审查报告.md`
 - 文件落盘：子agent 返回结构化审查报告后，**必须将审查报告原文写入** `trace_path/<节点执行序号>_后端测试审查_审查报告.md`

**下一个节点**：
  - PASS → `后端代码开发`
  - FAIL → `后端测试用例`修改测试（连续 FAIL 达 3 次触发回退熔断，**返回 FAIL 给主流程**）

---

## 节点：后端代码开发（绿）

**流程编排规则文件**：`.claude/nodes/bdd_feature/bdd_code_green.md`

**执行范围**：只编写后端实现代码（Python/FastAPI），使后端三层红灯测试转绿。不涉及前端代码。

**节点输入**：
  - 首次进入：`<doc>_后端测试用例开发结果包.md`、`<doc>_验证矩阵结果包.md`、`<doc>_架构基线结果包.md`、`<doc>_契约.<ext>`（如果存在）
  - 从`后端代码审查`节点进入：`<doc>_后端代码审查报告.md`

**节点结果**：`<doc>_后端代码开发结果包.md`（批次转绿状态、实现文件清单、绿灯确认、自检记录、待确认事项）

**下一个节点**：`后端代码重构`

---

## 节点：后端代码重构

**流程编排规则文件**：`.claude/nodes/bdd_feature/bdd_refactor.md`

**子agent**：`code-refactorer`（`.claude/agents/code-refactorer.md`），必须使用子agent在独立上下文中对当前**后端 git diff**的实现代码执行结构优化，禁止在主agent中直接重构

**节点输入**：
  - `<doc>_后端代码开发结果包.md`（实现文件清单、绿灯确认、自检遗留项）
  - `<doc>_架构基线结果包.md`
  - `<doc>_契约.<ext>`（如果存在，重构须保持契约不变）
  - `<doc>_验证矩阵结果包.md`（回归范围，重构后须保绿）
  - 当前后端 git diff（本次绿阶段后端实现改动，重构对象）

**节点结果**：`<doc>_后端代码重构结果包.md`（重构清单、绿验证复核记录、未重构项、契约保持核对、待确认事项）

**下一个节点**：
  - 全绿且契约未变 → 跳转`后端代码审查`
  - 存在回红且无法自修 → 跳转`后端代码开发`修复（计入代码重构回退环熔断计数，连续回退达 3 次触发熔断，**返回 FAIL 给主流程**）
  - 触及契约 → 停止重构，上报用户决策是否回退到主流程的`API契约`节点（属契约变更范畴，不计入回退熔断）

---

## 节点：后端代码审查

**流程编排规则文件**：`.claude/agents/bdd-stage-reviewer.md`

**子agent**：`bdd-stage-reviewer`（阶段参数 `code-green`），必须使用子agent在独立上下文中审查后端 git 改动，禁止在主agent中直接审查

**节点输入**：`<doc>_验证矩阵结果包.md`、`<doc>_架构基线结果包.md`、`<doc>_契约.<ext>`（如果存在）、`<doc>_后端代码开发结果包.md`、`<doc>_后端代码重构结果包.md`

**节点结果**：
 - 审查结论：PASS/FAIL、`<doc>_后端代码审查_审查报告.md`
 - 文件落盘：子agent 返回结构化审查报告后，**必须将审查报告原文写入** `trace_path/<节点执行序号>_后端代码审查_审查报告.md`

**下一个节点**：
  - PASS → 汇总各阶段记录，生成 `后端开发结果包.md`，**返回 PASS 给主流程**
  - FAIL → `后端代码开发`修改代码（连续 FAIL 达 3 次触发回退熔断，**返回 FAIL 给主流程**）

---

## 子流程结束

代码审查 PASS 后：
1. 汇总各节点记录到 `后端开发结果包.md`
2. 返回 PASS 给主流程；主流程读取本结果包判断是否进入下一阶段
