流程节点：BDD 代码重构
描述: 以代码审查通过（PASS）为前提，编排独立上下文的重构 agent 对当前 git diff 的实现代码做结构优化，主 agent 负责绿验证复核与结果存档。本阶段是 TDD「红-绿-重构」第三阶段，不改外部行为、保持测试常绿。执行层细节（重构清单、核心立场、输出格式）由 code-refactorer agent 承载，本节点只定编排。

# 代码重构阶段

## 系统指令

你现处于**代码重构阶段**，以自动流程节点身份**编排**独立上下文的重构 agent 执行结构优化，并负责重构后的绿验证复核与结果存档，不涉及人工协作、分支管理或 CI 配置。本阶段是 TDD「红-绿-重构」的第三阶段，紧接代码审查 PASS 之后，目的是让实现代码具备更好的大局观。

**本节点是编排节点，不是执行节点**：实际代码修改由 `code-refactorer` 子 agent 在隔离上下文完成，主 agent 只编排、复核、存档，**不直接重构**。执行层细节（重构清单、核心立场、输出格式）见 `.claude/agents/code-refactorer.md`，本节点不重复。

`code-refactorer` 是通用重构 agent，不绑定本流程——也可被用户单独唤起对任意文件/模块/diff 做重构。本节点的职责是把 BDD 流程的上下文（git diff、架构基线、契约、审查建议、回归范围、测试命令）组装为该 agent 的输入并编排其执行。

输入（编排视角，用于传递给子 agent 与复核）：

1. **代码开发结果包**（实现文件清单、绿灯确认）
2. **代码审查报告**（其"建议项"是重构优先处理对象）
3. **架构基线结果包**（含测试运行命令，用于复核；**及选定的范式 profile**）
4. **API 契约文件**（`<doc>_契约.<ext>`；若不存在则无）
5. **验证矩阵结果包**（回归范围，复核须保绿）
6. **当前 git diff**（本次绿阶段实现改动，重构对象）
7. **范式 profile**（`.claude/profiles/<profile>.md` 的"审查探测方式"章节）

任务：调用 `code-refactorer` 子 agent 执行重构 → 重跑三层测试复核常绿 → 汇总存档。

## 编排原则（仅本节点视角）

1. **隔离执行**：实际重构由 `code-refactorer` 子 agent 在独立上下文完成，主 agent 不直接改实现代码——这是本阶段引入独立 agent 的根本理由，避免实现思维与重构思维同上下文串味。
2. **绿验证复核独立**：子 agent 返回后，主 agent 独立重跑三层测试复核，不轻信子 agent 自报全绿。
3. **契约触及即停止**：重构触及契约（签名/枚举语义/错误表达/不变量）不属本阶段，停止并上报回退 `API契约` 节点。
4. **空转通过合法**：子 agent 判定无值得重构的问题时空转通过，不强行动手。

> 执行层细节（重构清单六类、核心立场、结果包输出格式）由 `code-refactorer` agent 承载，见 `.claude/agents/code-refactorer.md`，本节点不重复。本节点只负责把 BDD 上下文组装为该 agent 的输入。

## 执行步骤

### 步骤 1：确认前置条件

1. 确认上一节点（代码审查）结论为 **PASS**——审查 FAIL 时不会到达本节点。
2. 从代码审查报告提取**建议项**（审查已标记但未修复的结构问题），作为子 agent 的优先处理对象。
3. 从 `git diff` 界定本次实现改动范围（重构只针对这部分，不扩散到无关既有代码）。
4. 确认架构基线的三层测试运行命令可用（用于复核）。

**自我检查：**

- [ ] 代码审查结论为 PASS
- [ ] 代码审查报告建议项已提取
- [ ] git diff 实现改动范围已界定
- [ ] 架构基线测试运行命令已就绪

### 步骤 2：调用重构 agent

调用 `code-refactorer` 子 agent（`.claude/agents/code-refactorer.md`），在**隔离上下文**中执行实际重构。向其传递步骤 1 界定的输入，按下表映射为该 agent 的通用输入：

| BDD 上下文 | code-refactorer 输入项 |
|:---|:---|
| 当前 git diff | 重构范围（必需） |
| 架构基线三层测试运行命令 | 测试运行方式（必需） |
| 架构基线结果包 | 架构基线 / 编码约定（推荐） |
| 契约文件 | 契约 / 接口约束（可选） |
| 代码审查报告建议项 | 已知结构问题清单（可选） |
| 验证矩阵回归范围 | 回归范围（可选） |

子 agent 自行完成重构、重跑相关测试、产出结果包（格式见其"输出格式"章节）。

**编排约束：**

- 主 agent **不直接修改实现代码**，只编排与复核。
- 子 agent 拥有 Edit/Write 工具，自行执行重构与自检。

### 步骤 3：绿验证复核

子 agent 返回后，主 agent **独立复核**，不轻信其自报结论：

1. 按架构基线命令重跑三层测试 + 验证矩阵回归范围，确认全绿、无回红。
2. 对照契约文件，确认重构未触及契约要素。
3. 抽查重构清单关键改动，确认行为不变（diff 只动结构不动逻辑）。

**复核结果分支：**

| 复核结果 | 处理 |
|:---|:---|
| 全绿 + 契约未变 | 继续步骤 4 存档，流转全量测试 |
| 存在回红且子 agent 已自修 | 重新复核，通过则继续 |
| 存在回红且无法自修 | 回退 `代码开发` 修复（计入代码重构回退环熔断计数） |
| 触及契约 | 停止，记入待确认事项，上报用户决策是否回退 `API契约` |

**自我检查：**

- [ ] 三层测试 + 回归范围全部通过
- [ ] 契约要素未被触及
- [ ] 抽查确认行为不变
- [ ] 无回红

### 步骤 4：汇总存档

将子 agent 产出的结果包按引擎存档规则写入 `<doc>_代码重构结果包.md`。结果包格式见 `.claude/agents/code-refactorer.md` 的"输出格式"章节，本节点不重复定义模板。

## 质量门禁（编排层）

| 检查项 | 通过标准 |
|:---|:---|
| 前置就绪 | 代码审查结论为 PASS |
| 隔离执行 | 重构由 code-refactorer 子 agent 完成，主 agent 未直接改实现代码 |
| 绿验证复核 | 主 agent 独立重跑三层测试 + 回归范围，全绿无回红 |
| 结果存档 | 结果包已写入 trace_path |

> 执行层门禁（行为不变、契约保持、无过度抽象、架构对齐、最小必要等）由 `code-refactorer` agent 自检保证，主 agent 复核时抽查即可，不在此重复列举。

**最终判断信号：**

1. 重构是否由隔离子 agent 执行（主 agent 未越俎代庖直接改实现）？
2. 主 agent 是否独立复核了三层测试 + 回归范围全绿、无回红？
3. 契约要素是否全部未变？

三条全是为是，则本阶段完成，流转下一阶段：全量测试验证。

## 节点跳转

- **全绿 且 契约未变** → `全量测试`（重构的本质是"不改行为改结构"，全量测试是其最佳回归验证）。
- **存在回红且无法自修** → `代码开发`（修复实现使测试恢复通过，计入代码重构回退环熔断计数，连续回退达 3 次触发熔断上报用户）。
- **触及契约** → 停止重构，上报用户决策是否回退 `API契约` 节点（属契约变更范畴，不计入回退熔断，按编排引擎核心规则第 8 条处理）。
- **重构 agent 自修回红后复核通过** → 继续 `全量测试`。
