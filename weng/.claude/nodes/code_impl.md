# 流程节点：功能代码实现

## 核心理念

**镜像现有**：新代码必须自然融入现有代码库的风格与模式，写任何代码前先理解，最好的新代码读起来就像旧代码一样自然。
**黄金法则**：发现问题立即修复。永远不在已知的错误代码上进行开发
**迭代哲学**：不要对需求意外的代码进行修改，所有的改动都是为了目标需求

## 前置条件

### 项目运行环境检测

- 识别项目编译、运行环境
- 确认项目配置文件（如 `.env`）已配置
- 确认项目数据库已连接
- 识别测试环境与编译命令

### Git 状态检测

| 当前状态 | 操作 |
|:---|:---|
| 分支干净 | 开始任务 |
| 存在未提交变更 | **停止** - 让用户先处理 |

## 执行流程

### 1. 需求加载

读取加载需求共识与改动计划文件

### 2. 执行

逐步执行每个改动任务：
1. **实现** - 严格遵守项目规范编写代码
2. **立即验证** - 每个人物完成需要验证代码是否符合需求与计划
3. **跟踪进度** - 记录每个任务的完成情况，更新进度报告，标注任务为完成

**处理偏差**：
- 记录**什么**与计划出现偏差
- 记录**为什么**出现偏差
- 记录**如何**解决偏差
- 偏差信息在报告中记录

### 3. 验证

1. 静态分析：自动修复lint错误
2. 自动测试：**验证矩阵全覆盖**，用例、需求、代码实现保持一致。
