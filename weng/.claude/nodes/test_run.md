# 流程节点：运行用例并统计结果

## 目标

运行全量测试，验证所有改动正确无误。如果存在失败，记录失败用例的详细信息

## 前置条件

- 代码审查已通过
- 后端测试基础设施完备

## 执行流程

运行测试并返回记录测试结果。

```markdown
# 测试运行结果

## 运行信息
- 运行时间：{timestamp}
- 总用例数：{total}
- 通过：{passed}
- 失败：{failed}
- 错误：{errors}

## 失败用例详情

### {test_name} FAILED
- 文件：{file_path}:{line}
- 错误类型：{error_type}
- 错误信息：{error_message}
- 失败分类-仅供参考：{测试代码错误 / 业务代码错误 / 环境问题}
```

### 3. 失败分类与路由

对每个失败用例进行简单分类判断：

#### 分类标准

| 失败类型 | 特征 |
|:---|:---|
| **测试代码错误** | 断言逻辑错误、Mock 未正确设置、测试数据无效、fixture 问题 |
| **业务代码错误** | 实际返回值与预期不符、逻辑 bug、遗漏实现、异常处理缺失 |
| **环境问题** | 依赖缺失、配置错误、数据库连接失败 |
| **无法判断** | 失败原因不明确 |
