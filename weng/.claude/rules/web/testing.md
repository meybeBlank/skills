# Web测试规则

## 优先级顺序

### 1. 视觉回归

- 在关键断点截图：320、768、1024、1440
- 测试英雄区域、滚动叙事区域和有意义的状态
- 对视觉密集型工作使用Playwright截图
- 如果存在两种主题，测试两者

### 2. 无障碍

- 运行自动化无障碍检查
- 测试键盘导航
- 验证减少动画行为
- 验证颜色对比度

### 3. 性能

- 对有意义的页面运行Lighthouse或等效工具
- 保持 [performance.md](performance.md) 中的CWV目标

### 4. 跨浏览器

- 最低要求：Chrome、Firefox、Safari
- 测试滚动、动画和回退行为

### 5. 响应式

- 测试 320、375、768、1024、1440、1920
- 验证无溢出
- 验证触摸交互

## E2E测试结构

```ts
import { test, expect } from '@playwright/test';

test('着陆页英雄加载', async ({ page }) => {
  await page.goto('/');
  await expect(page.locator('h1')).toBeVisible();
});
```

- 避免基于超时的不稳定断言
- 优先使用确定性等待

## 单元测试

- 测试工具函数、数据转换和自定义hooks
- 对于高度视觉化的组件，视觉回归通常比脆弱的标记断言提供更多信号
- 视觉回归补充覆盖率目标；不替代它们
